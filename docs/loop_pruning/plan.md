## 1. 方針

- **主張の置き方**：「重みを共有したループ型 Transformer のための、**再学習なし**の構造化 Pruning」に絞るのが最も強い。再学習なしの Pruning は NeurIPS 2022〜2026 で継続して採択されている（§2）。今回の結果でも、提案が明確に勝つのは再学習なしの条件である。
- **ステップ削減の扱い**：手法としては使わない。参照線（bViT 論文 Fig. 2(a) に対応）と、**併用の相手**として扱う。「ステップを減らせば済むのでは」には「併用できる」と答える（2026-11-17 にユーザーが決定、§4 Q1）。
- **現状で足りないもの**は大きく 4 つ。
  1. ImageNet-1K 規模の結果（現状は 64×64 と 32×32 のみ）
  2. 最新の再学習なし手法との比較（現状のベースラインは bViT 論文の式と自作の対照のみ）
  3. 重要度の妥当性の直接検証（「重要度に着目」という主題の裏づけ）
  4. bViT 以外のループ型モデルでの検証
- **最初にやること**は、追加学習なしでできる分析（フェーズ 0 と 0'、1〜2 週間）。ここで主張が成り立つかを判定してから、計算資源のかかる作業に進む。

## 2. 参考にしたトップ会議論文と、そこから読み取れる水準

| 論文 | 会議 | 本研究との関係 | 評価の水準 |
|---|---|---|---|
| Kwon et al., A Fast Post-Training Pruning Framework for Transformers | NeurIPS 2022 | 再学習なし、Fisher、マスク探索・並べ替え・出力再構成。**最も近い先行研究** | BERT / DistilBERT、GLUE・SQuAD。再学習ありの手法とも比較。Pruning にかかる時間（数分）を報告。較正サンプル数の感度 |
| SnapViT（Elastic ViTs from Pretrained Models without Retraining） | NeurIPS 2025 | 再学習なし、勾配＋構造間の相関（Hessian 非対角の近似）。**交差項の考え方が近い** | DINO / SigLIPv2 / DeiT / AugReg と複数の事前学習モデル。Pruning 時間「A100 1 枚で 5 分未満」を報告 |
| CORP（Closed-Form One-shot Representation-Preserving Structured Pruning） | arXiv 2602.05243（NeurIPS 2026 採択と記載） | 再学習なし、消した単位を残した単位の線形結合で補償（リッジ回帰の閉形式）。**平均置換の上位互換になりうる** | DeiT（Huge まで）、ImageNet。ラベルなし較正 |
| NViT（Global ViT Pruning with Hessian-Aware Saliency） | CVPR 2023 | 2 次の重要度、全体順位、遅延を考慮 | DeiT-B、ImageNet-1K。FLOPs・パラメータ・**実測速度**（GPU 1 枚、バッチ 256）を併記。微調整あり |
| SNP（Structured Neuron-level Pruning） | ECCV 2024 | QK と V を別々に削る点が同じ | DeiT-S ほか。Raspberry Pi 4B など**エッジ実機の遅延** |
| WDPruning / ViT-Slim / SAViT / X-Pruner | AAAI・CVPR・NeurIPS 2022〜23 | ViT の構造化 Pruning の定番ベースライン | DeiT-T/S/B、ImageNet-1K、微調整あり |
| SliceGPT | ICLR 2024 | 関数を保つ回転のあとに削る（基底回転と同じ発想） | 複数モデル、再学習なしと軽い微調整の両方 |
| Molchanov et al., Importance Estimation for Neural Network Pruning | CVPR 2019 | ゲート勾配の重要度。bViT 論文もこれを引用 | **重要度と「実際に消したときの損失変化」の相関**を直接検証 |
| bViT（Byra et al.） | arXiv 2605.10661 | 対象モデル | ImageNet-1K、300 エポック、H100 × 4。コードは未公開（本文で伏せ字）。Fig. 2(a) で各ステップで打ち切った精度を分析として報告 |

読み取れる共通点：

- **ImageNet-1K（224×224）と DeiT 系列が事実上の必須条件**。小規模データだけの Pruning 論文はトップ会議ではほぼ通らない。
- 再学習なしの論文は、**較正データ量の感度**と **Pruning にかかる時間**を必ず示す。
- 速度を主張する論文は、**実機での実測**を FLOPs と並べて示す。
- 「同じ計算量の小さいモデルを最初から学習した場合」との比較がある。
- 重要度を主題にする論文は、**重要度の予測と実測の一致**を示す。

### 新規性の確認（2026-11-17 時点の検索）

- ループ型・重み共有 Transformer に対して、ステップ別の幅を決める構造化 Pruning の論文は見つからなかった。検索は数回で、網羅的ではない。投稿前に再確認が必要。
- 近い方向の最近の論文は次のとおり。
  - LoopFormer（arXiv 2602.11451）：ループ回数を可変にする言語モデル。幅は削らない。
  - Rethinking Depth Pruning for Vision Transformers（arXiv 2607.03784）：深さの Pruning。ステップ削減側の関連研究として読む必要がある。
- 個々の要素（Fisher、非対角項、回転、平均置換、FLOPs 当たりの順位）はすべて既知である。新規性は「重み共有によって生じるステップ間の相互作用」と「ステップをまたぐ配分」にしかない。ここを分析で裏づけないと「既存技術の組み合わせ」と評価される。

## 4. 査読で問われる点と答え方

**Q1. ステップを減らせば済むのでは。**（最大のリスク）

- 答えの軸：**「ステップ削減と競合せず、併用できる」**（方針、§1）。
- 現状の事実（結果 §5.7、§5.9）：
  - 再学習なしでは、提案のみでもステップ削減のみより上。併用はさらに +1〜2pt。
  - CPU では、同じ精度で併用がステップ削減のみより速い（低精度域で最大 +25〜30%）。
  - GPU（2080Ti）では、同じ精度で併用とステップ削減のみがほぼ同等。上回らない。原因は圧縮実装の固定費。
  - 3 エポックの微調整後は、−50% でステップ削減のみが提案のみに並ぶか上回る。併用での微調整後は未検証。
- 補強の候補：
  1. 併用の結果を他設定・微調整後でも示す（フェーズ 0'）。
  2. 実装の固定費を除き、GPU でも併用が上回るかを確かめる（作業 1-4）。
  3. ステップ削減は刻みが粗い（12 段階、1 段で FLOPs 8%）のに対し、併用なら連続的に調整できることを示す。
  4. 主張の中心を再学習なしに置く（Kwon、SnapViT、CORP と同じ立場）。

**Q2. 小さいデータセットでしか試していない。** → ImageNet-1K（§6）。

**Q3. 既存の基準をステップ別に当てただけではないか。** → 最新手法を「共通マスク」と「ステップ別（各ステップ独立）」の 2 通りで移植し、提案との差が交差項と配分から来ることを示す。

**Q4. bViT 専用の手法ではないか。** → ALBERT など、公開重みのある重み共有モデルで再現する（フェーズ 3）。

**Q5. 削った bViT は、最初から小さいモデルより良いのか。** → bViT-B を −70% 削ったもの（3.4 GFLOPs）と bViT-S（2.8 GFLOPs）の比較など。

**Q6. 平均置換より良い補償があるのでは。** → CORP 方式（残した単位による線形補償）を取り込んで比較する。良ければ提案に組み込む。

**Q7. パラメータがほとんど減らないのでは。**（結果 §5.10）

- 現状の事実：FLOPs −50% で保存パラメータは −6.5〜6.8%。パラメータ数で比べると、ループ非対応の共通マスクが上。現在の実装は、実行時にステップごとの重みのコピーを持つ（未枝刈りの 3〜10 倍）。
- 答え方の候補：
  1. bViT はもともとパラメータが ViT の 1/12 で、ボトルネックは FLOPs であることを示し、目的を計算量の削減と明示する。比較は同じ FLOPs で行う。
  2. 実行時にコピーを作らない実装（共有行列から行を取り出す）にして、速度の代償を測る。
  3. パラメータも減らしたい場合への拡張として、共有重みに残す単位数に罰則をかける配分（全ステップで使われない単位を増やす）を検討する。

## 5. 作業計画

期間は 2080Ti 1 枚での見積もり。フェーズ 2 だけは計算資源しだいで大きく変わる。

### フェーズ 0：主張の検証（1〜2 週間、追加学習なし）

既存の 3 つのチェックポイントだけで実施できる。**ここで主張が成り立たなければ、設計に戻る。**

| 作業 | 内容 | 合格の目安 |
|---|---|---|
| 0-1 重要度のオラクル検証（**主要部分は実施済み、結果 §5.11**。ランダム単位 420 件、複数単位の同時除去は未実施） | ランダムに選んだ (ステップ, 単位) を実際に消し、損失変化の実測と各重要度（論文の式、Fisher、平均置換 Fisher）の順位相関を測る | 提案の相関が論文の式より明確に高い |
| 0-2 交差項の検証（**実施済み、結果 §5.11**：相互作用の順位相関 0.89〜0.94） | 同じ単位を 2 ステップで同時に消したときの実測損失を、交差項あり・なしの予測と比べる | 交差項ありの予測誤差が小さい |
| 0-3 交差項の構造 | `F_i[t,s]` のステップ × ステップのヒートマップ（層別の平均）。符号、隣接ステップとの関係 | 明確な構造がある（論文の図になる） |
| 0-4 較正の感度 | 較正 128 / 512 / 2,048 / 10,240 枚、ラベルなし（モデルの予測をラベルに使う） | 2,048 枚以下で精度が飽和 |
| 0-5 Pruning 時間 | 重要度計測から圧縮までの所要時間 | 数分程度 |
| 0-6 通常の ViT との対比 | 同じ手法を重み非共有の ViT（学習済みの `vit_*_scratch`）に当てる。配分の自由度の効果と交差項の大きさを比べる | ループ型のほうが効果が大きい |
| 0-7 微調整レシピの修正 | 未枝刈りモデルが劣化しないレシピ（未枝刈りモデルを教師にした蒸留、lr を下げる、10 エポック程度） | 未枝刈りの対照が元の精度を保つ |

0-6 は「ループ構造に適した」という題目の根拠になる。結果が逆（通常の ViT でも同じだけ効く）なら、主張を「ステップ別マスクの配分」一般へ広げるか、ループ固有の要素を強める必要がある。

### フェーズ 0'：ステップ削減との併用の追加検証（1 週間程度、C のみ微調整あり）

併用 A（結果 §5.9）の続き。Q1 への答えを固める。

| 作業 | 内容 | 合格の目安 |
|---|---|---|
| B 足し算性の定量化 | 併用の利得を「ステップ削減の利得 ＋ 提案の利得」と比べ、重なりの大きさを測る。提案の配分で、もともと削られていた終盤ステップの割合と対応づける | 重なりの理由を配分の図で説明できる |
| C 微調整後の比較 | 同じ FLOPs で「8 回 ＋ 提案」対「6 回のみ」などを、0-7 の修正レシピで微調整して比べる | 微調整後も併用が上回る（査読対策として最重要） |
| D 適用の順序 | 12 回で作ったマスクから後ろのステップを落とす方式と、打ち切ったモデルで測り直す方式（A で採用）を比べる | 測り直しの必要性を判断できる |
| E 他設定と統計 | CIFAR-100 の bViT-S / bViT-B で A を再現。S / Tiny で較正 seed 3 回 | 3 設定で傾向が一致 |
| F GPU 再測定 | 作業 1-4 で固定費を除いたあとに、併用の GPU 速度を測り直す | 同精度でステップ削減のみを上回る |

C と E を優先する。F はフェーズ 1 の 1-4 のあと。

### フェーズ 1：比較と速度の強化（3〜4 週間）

## 6. ImageNet-1K をどう用意するか

bViT 論文の学習は 300 エポック、H100 × 4 である。コードと重みは公開が確認できなかった。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A | 著者に重み・コードの提供を依頼 | 論文と同じモデルで比較できる | 返事が来る保証がない |
| B | 自前で学習（bViT-S、エポックを 100 程度に短縮） | 自分で制御できる | 2080Ti 1 枚では数週間かかる見込み（未計測。`model_profile.py` で学習スループットを測って見積もる）。精度は論文より下がる |
| C | ImageNet-100（224×224）を中間段階にする | リポジトリが対応済み。数日で学習可能 | これだけでは査読で不足 |
| D | 大学の共用計算機やクラウドを使う | bViT-B の 300 エポックが現実的になる | 申請と費用 |

## 10. 既存の ViT ＋ 既存の構造化 Pruning との比較の計画と設計（2026-11-17 改訂 2）

**方針（2026-11-17 ユーザー決定）**：
- 新しく学習せず、**手元にある学習済みの ViT** を使う。
- 主な比較は「**ViT-S に既存の構造化 Pruning を当てたもの**」対「bViT-S ＋ 提案」。どちらも CIFAR-100 で、同じ FLOPs。
- ImageNet-1K の DeiT は使わない。
- 再学習（微調整）は後で検討する。それまでは再学習なしで比べる。

既存手法を bViT に移植する比較は、補助として 10.7 に残した。

### 10.1 使うモデル（学習済み、すべて CIFAR-100・同じレシピ）

ViT-S / ViT-B と bViT-S / bViT-B の学習設定は、モデル名以外すべて同じであることを config で確認した（AdamW、lr 5e-4、実効バッチ 1024、300 エポック、mixup / cutmix、RandAugment、EMA、seed 42）。FLOPs は全演算、`model_profile.py` で 2026-11-17 に測定。

| モデル | パラメータ | GFLOPs | top-1（final_eval） | チェックポイント |
|---|---|---|---|---|
| **ViT-S**（12 層、重み非共有） | 21.37M | 2.84 | **73.26%** | `outputs/bvit/vit_s_scratch_cifar100_20261027_192724/best.pth` |
| **bViT-S**（1 ブロック × 12 回） | 1.86M | 2.84 | 68.75% | `outputs/bvit/bvit_s_cifar100_20261027-140057/best.pth` |
| ViT-B（12 層） | 85.20M | 11.20 | 67.47% | `outputs/bvit/vit_b_scratch_cifar100_20261104_231307/best.pth` |
| bViT-B（1 ブロック × 12 回） | 7.25M | 11.20 | 69.88% | `outputs/bvit/bvit_b_cifar100_20261029_153422/best.pth` |

- 主な比較は S の組。B の組は追加の学習なしで作れるので、2 つ目の組として載せる。
- Tiny-ImageNet の ViT はないので、比較は CIFAR-100 だけになる。

### 10.2 この形式の見通し（予想と、示せること）

**削る前の時点で、ViT-S が bViT-S より 4.5pt 高い**（73.26% 対 68.75%）。これを踏まえると、次の見通しになる。

| 軸 | 予想 | 根拠 |
|---|---|---|
| 精度対 FLOPs | 削減率が小さいうちは ViT-S ＋ 既存手法が上、削減率が大きくなると逆転する可能性がある | bViT-S ＋ 提案は FLOPs −50% で 64.34%（9pt 低下）。再学習なしの既存手法は、ViT で 50% 削ると大きく落ちる（例：CORP の DeiT-S、MLP と注意の両方を 50% で 79.8% → 58.47%） |
| 精度対パラメータ | bViT-S ＋ 提案が大きく左上 | bViT-S は削る前から 1.86M で、ViT-S の 9% |
| B の組 | bViT-B ＋ 提案がほぼ全域で上 | 削る前から bViT-B が 2.4pt 高く、FLOPs −50% でも 67.96% と、削る前の ViT-B（67.47%）を上回る |

示したいこと：

| 仮説 | 内容 | 成り立たなかった場合 |
|---|---|---|
| G1 | 精度対 FLOPs で、少なくとも大きな削減率（−50% 以上）では、bViT-S ＋ 提案が ViT-S ＋ 既存手法を上回る | 主張を「パラメータあたりの精度」と「B の組」に寄せる |
| G2 | 精度対パラメータで、bViT ＋ 提案が ViT ＋ 既存手法より左上にある | （予想どおりなら成り立つ。ただし重み共有によるもので、手法の貢献ではないことを本文で明記する） |
| G3 | 同じ ViT-S に当てると、提案は既存手法と同等以上になる（フェーズ 0 の 0-6） | 手法の貢献を「ループ型への対応」に絞る |

G1 が成り立つかは、ViT-S を再学習なしで削ったときにどれだけ精度が落ちるかで決まる。小さいデータで学習した ViT の再学習なし Pruning の数値は、文献にほとんどないので、実際に測るしかない。

### 10.3 ViT-S に当てる既存の構造化 Pruning 手法（再学習なし）

各手法を本来の対象（重み非共有の ViT）に、本来の単位で当てる。原則として公式コードをそのまま使う。

| 優先 | 手法 | 会議 | 単位 | コード |
|---|---|---|---|---|
| A | CORP | NeurIPS 2026 | MLP、Q/K 次元 ＋ 線形補償 | あり（timm 対応） |
| A | VBP | ICCV 2025 | MLP ＋ 平均補償 | あり（DeiT 対応） |
| A | SnapViT | NeurIPS 2025 | ヘッド・MLP | あり（プロジェクトページ） |
| A | Kwon et al. | NeurIPS 2022 | ヘッド・MLP ＋ 再構成 | あり。ただし BERT 用なので ViT への移植が要る |
| B | OPTIN | ICLR 2024 | ヘッド・MLP | あり |
| 対照 | 重みの大きさ（L1）、Taylor（1 次） | − | ヘッド・MLP | 自作（数十行） |
| 対照 | 提案を ViT-S に当てたもの | − | FFN・QK・V | 既存の `prune_loop_bvit.py` を流用（0-6） |

- 単純な対照（L1、Taylor）は、既存手法の移植がうまくいっているかの目安にもなる（既存手法がこれより悪ければ移植を疑う）。
- **公式コードで当てるための変換**：手元の ViT は RecurrentViT クラスで、RMSNorm を使い、q / k / v が別々の Linear である。`norm_layer` を RMSNorm にした timm の `VisionTransformer` を作り、q / k / v を連結して qkv に移す変換を書く。変換前後で出力が一致すること（最大誤差 1e-4 以下、CIFAR-100 の検証精度 73.26% が一致）を確かめる。LayerNorm を前提に補償を畳み込む手法があれば、RMSNorm で式が変わらないかを個別に確かめる。
- 再学習ありの手法（DepGraph ＋ 微調整など）は、再学習の扱いが決まってから加える。

### 10.4 グラフの設計

CIFAR-100 で、S の組と B の組それぞれについて、次の 2 枚を描く（計 4 枚。S の組が主図）。2 つの量を 1 枚の左右の縦軸に重ねることはしない。

| 図 | 横軸 | 縦軸 |
|---|---|---|
| 精度対 FLOPs | GFLOPs（線形）。圧縮後のモデルを全手法で同じカウンタで測る | top-1 |

各図の系列：

| 系列 | 表し方 | 意味 |
|---|---|---|
| ViT-S ＋ 各既存手法 | 手法ごとに色を固定した実線 | 主な比較相手 |
| bViT-S ＋ 提案 | 強調色の太線 | 提案 |
| ViT-S ＋ 提案 | 強調色の細い破線 | 手法だけの効果（G3） |

FLOPs の目標は、各モデルの削る前から −10〜−70% の 7 点（提案と同じ）。各手法の削減率は二分探索で FLOPs に合わせる。付録として、精度対 GPU スループット（バッチ 256）の図も作る。提案の実装には GPU 上の固定費が残っているので（作業 1-4）、主図には入れない。

### 10.5 公平性のための条件

| 項目 | 揃え方 |
|---|---|
| 学習 | すでに同じレシピ・同じ seed で揃っている（10.1） |
| 計測 | FLOPs、パラメータ、スループットは、圧縮後のモデルを全手法で同じスクリプトで測る。幅は全手法で 8 の倍数に丸める |
| 較正データ | CIFAR-100 の学習画像から同じ集合を使う。枚数は各手法の既定と、共通の 4,096 枚の 2 通り |
| ラベル | 提案の Fisher はラベルを使う。ラベルなしの手法（CORP、VBP、SnapViT）と揃えるため、モデルの予測を疑似ラベルにした提案も併記する |
| 再学習 | なし（全手法）。再学習ありの比較は後で検討する |
| 統計 | 較正の seed 3 回の平均と標準偏差。学習の seed は 1 回で、限界として明記する |

### 10.6 実装の設計

- `export_timm.py`（新規）：`vit_*_scratch` を timm の `VisionTransformer` に変換し、出力と精度の一致を確かめる。
- `prune_vit_baselines.py`（新規）：変換した ViT に各手法を当てる入口。手法ごとに「削減率 → マスク → 圧縮モデル」を呼び、二分探索で FLOPs 目標に合わせる。結果は今と同じ records 形式で `outputs/vit_pruning_baselines/<model>_cifar100/results.json` に書く。公式コードは `third_party/`（git 管理外）に置く。
- 提案を ViT-S に当てる部分（0-6）：`prune_loop_bvit.py` は RecurrentViT を前提にしているので、重み非共有（12 ブロック × 1 回）でも動くかを確かめ、必要なら直す。
- `prune_compare_report.py`（新規）：bViT の `results_mc.json` / `params.json` と ViT の結果を読み、10.4 の図（png、docs 用）と表を作る。
- W&B：表だけを送る（job_type は `vit_baseline` と `compare_report`）。W&B 上で散布図を描けるように、model、method、gflops、params、top1 の列を必ず入れる。図は送らない。

### 10.7 補助：既存手法の bViT への移植

モデルを bViT に固定して、手法の差だけを見る比較。査読の Q3「既存の基準をステップ別に当てただけでは」への答えになる。主比較（10.1〜10.6）が済んでから、CORP と VBP に絞って行う。

- 共通版（共有ブロックを 1 層とみなし、全ステップ共通のマスク）と、展開版（12 層とみなし、ステップ別のマスク）の 2 通りで当てる。
- 線形補償（CORP、Kwon の再構成）を展開版で使うと、後段の重みがステップごとに変わる。そのため重み共有が壊れ、保存パラメータが最大 12 倍になる。ステップ別・共有・低ランクのステップ別の 3 通りで比べる。
- 平均置換は VBP がすでに使っているので、新規性として主張できない。主張できるのは「平均に置き換えたときの損失増加を、ステップ別に交差項込みで測ること」である。

### 10.9 決めてほしいこと

1. **B の組（ViT-B 対 bViT-B）も載せるか。** 追加の学習なしで作れ、bViT 側が有利な組。ただし、ViT-B が ViT-S より低い（67.47% 対 73.26%）のは小さいデータでの過学習と考えられる。そのため「弱い ViT を相手にしている」と見られる恐れがあり、主図は S の組にしたい。
2. **段階 1 の結果を見てから、主張の軸を決めるか。** ViT-S が再学習なしの Pruning に強い場合は、G1（FLOPs 軸での勝ち）は小さい削減率では成り立たない。そのときは、パラメータ軸（G2）と、大きな削減率での比較を主にする。
