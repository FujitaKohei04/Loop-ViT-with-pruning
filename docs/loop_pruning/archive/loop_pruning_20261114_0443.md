# ループ構造に適した構造化 Pruning（bViT）

> 旧版（2026-11-17 に [results.md](../results.md) と [plan.md](../plan.md) へ整理済み）。最新はそちらを参照。

作成：2026-11-14 04:43　／　対象：bViT-S（Tiny-ImageNet、CIFAR-100）、bViT-B（CIFAR-100）

## 要旨

1つのブロックを 12 回繰り返す bViT について、**繰り返し構造を考慮した構造化 Pruning** を設計・実装し、計算量削減を評価した。ステップ削減やトークン削減は差別化のため手法には使わず、参照線としてのみ載せる。

提案手法の要点は次の 4 つ。

- 削る単位：「ステップ × FFN ニューロン／QK チャネル／V チャネル」。残差側の次元には触れないので、行列そのものが細くなる。
- 重要度：同じ単位を別のステップでも消したときの相互作用（**ステップ間交差項**）を入れた Fisher で測る。消した単位は 0 ではなく**ステップごとの平均出力**で置き換え、重要度もその置き換えを基準に測る。
- 配分：全ステップ・全層を **FLOPs 当たりの損失増加**で 1 列に並べ、FLOPs 目標まで削る。
- 前処理：ヘッドごとに特異値基底へ回転する（関数は不変）。

主な結果（再学習なし）：

| FLOPs −50% での top-1 | 未枝刈り | bViT 論文の重要度（同じ単位） | **提案** | ステップ削減 12→6 |
|---|---:|---:|---:|---:|
| bViT-S / Tiny-ImageNet | 55.7 | 25.0 | **49.6** | 40.9 |
| bViT-S / CIFAR-100 | 68.8 | 25.7 | **64.3** | 54.6 |
| bViT-B / CIFAR-100 | 69.9 | 49.6 | **68.0** | 64.4 |

- 論文の step-specific pruning の重要度を同じ単位に当てた場合と比べ、精度は大幅に上がった。3 設定すべてで、同じ FLOPs のステップ削減も上回った。
- 精度低下を 2pt 以内に収めたときの FLOPs 削減は、提案が −30〜−50%、ステップ削減が −25〜−33%。
- 弱点 1（速度）：RTX 2080Ti で実測すると、同じ精度でもステップ削減より 15〜30% 遅い。CPU では、高削減域で提案が 13〜17% 速い。バッチ 1 の遅延は未枝刈りより悪化する。
- 弱点 2（微調整後）：マスクを固定して 3 エポック微調整すると、FLOPs −50% ではステップ削減が追いつく、または上回る。提案の優位が残るのは高削減域（−70%）。

## 1. 背景と目的

bViT [1] は、ViT [2] の 12 個のブロックを 1 個の共有ブロックの 12 回適用（以下「ステップ」）に置き換えたモデルである。パラメータは 1/12 になるが、FLOPs は ViT と同じなので、推論の計算量を減らす手段が要る。

bViT 論文は step-specific pruning を提案している。共有重みの特異値方向に、ステップごとに別のマスクをかける方式である。本研究の課題意識は次のとおり。

- 既存の Pruning は層ごとに独立な重みを前提にしており、**同じ重みを繰り返し使うことを重要度や配分に反映していない**。
- bViT 論文の方式は低ランク分解になるため、**計算量がほとんど減らない**（§2）。

目標は、**精度を保ったまま FLOPs とスループットを改善する**こと。特に**重要度の測り方**に着目する。

## 2. 既存手法と問題点

| | bViT step-specific [1] | 一般的な構造化 Pruning [5,7,15] | 本研究 |
|---|---|---|---|
| 単位 | 重みの特異値方向 | ニューロン・チャネル・ヘッド | ニューロン・チャネル |
| マスク | ステップ別 | **全ステップ共通**（ループ非対応） | ステップ別 |
| 重要度 | \|バッチ平均勾配\|（1 次、ステップ独立） | Taylor／Fisher（層独立） | Fisher ＋ **ステップ間交差項**、平均置換を基準 |
| 配分 | 各ステップ・各層で同じ割合 | 層をまたぐ順位など | **ステップ × 層をまたぐ順位**（FLOPs 当たり） |
| 計算量 | 低ランク化（2 つの積）のため減りにくい | 減る | 減る |

bViT 論文の方式をそのまま実行すると（[pruning_compute.md](../../pruning_compute/pruning_compute.md) の計測を再掲）、bViT-S / Tiny-ImageNet では FLOPs −24% で top-1 40.0%、−53% で 9.2% だった。スループットは 0.73〜1.06 倍で、ほとんど速くならない。

## 3. 提案手法

### 3.1 削る単位

| 単位 | 消す行列要素 | 1 単位（1 ステップ分）の FLOPs（bViT-S、65 トークン） |
|---|---|---:|
| FFN ニューロン | fc1 の行 ＋ fc2 の列 | 99,840 |
| QK チャネル | q の行 ＋ k の行 | 108,290 |
| V チャネル | v の行 ＋ proj の列 | 108,290 |

残差側（384 次元）は削らない。マスクはステップごとに持ち、推論時はステップ t でそのステップ用に細くした重みを使う。V チャネルがすべて消えたヘッドは、QK も計算不要なので追加で除去する。

### 3.2 前処理：ヘッドごとの基底回転（`rot`）

ヘッド h について、`proj_h · v_h` と `q_hᵀ k_h` をそれぞれ特異値分解し、重みをその基底へ書き換える。

- V 側：`v' = M v`、`proj' = proj M⁻¹`
- QK 側：`q' = M q`、`k' = M⁻ᵀ k`
- バイアスも同じ変換を受ける。

出力は変わらない（最大誤差 5e-7）。回転後は情報が少数のチャネルに集まるので、削りやすくなる。EigenDamage [10] や SliceGPT [11] と同じ発想だが、ここでは**単位を選ぶための基底**としてだけ使う。計算は普通の細い行列積のままである。

### 3.3 重要度：平均置換に対する Fisher ＋ ステップ間交差項

各単位の出力にゲートを付け、画像 n・ステップ t・単位 i ごとの損失変化への寄与 `g[n,t,i]` を測る。

- 除去の定義は「出力 x を、そのステップでの平均 μ に置き換える」とする（§3.5）。そのため `g[n,t,i] = Σ_tokens ∂L/∂x · (x − μ)` とする。
- 損失増加を 2 次近似し、Hessian を Fisher で近似する [3,4,6]。

  `F_i[t,s] = E_n[ g[n,t,i] · g[n,s,i] ]`

  - 対角項（t = s）は通常の Fisher 重要度。
  - 非対角項（t ≠ s）は、同じ単位をステップ t と s の両方で消したときの相互作用。**重みを共有したループでのみ現れる量**で、本研究の中心である。
- すでにステップ集合 S で消した単位 i を、さらにステップ t で消すときの追加コスト：

  `ΔL ≈ ½ F_i[t,t] + Σ_{s∈S} F_i[t,s]`

比較対象の bViT 論文の重要度は `|E_n g[n,t,i]|` である。ステップ間の相互作用がなく、学習済みモデルでは平均勾配がほぼ 0 になるため、雑音に近い。

### 3.4 配分：ステップ × 層をまたぐ 1 本の順位

全 (ステップ, 層, 単位) を `ΔL ÷ 削減 FLOPs` の小さい順に貪欲に除去し、交差項は除去のたびに更新する。目標 FLOPs に達したところで止める（目標は二分探索で合わせる）。「各ステップから同じ割合」という制約がないので、ステップごとの役割の違いが配分に表れる（§5.6）。

### 3.5 平均置換（ステップ別バイアスへの畳み込み）

消した単位の出力を 0 ではなく、較正データでのステップ t の平均 μ_t に置き換える [12,13]。μ_t は定数なので、次の層（fc2 / proj）のステップ別バイアスに `W[:, removed] · μ_t[removed]` として足し込む。推論時の追加 FLOPs は 0、追加パラメータは 12 ステップ × 384 × 2 = 9,216（bViT-S）。

重要度も「平均に置き換えたときの損失変化」で測る（§3.3）。0 置換で選んだマスクに後から平均補正だけを足す方式（`+bc`）より、明確に良かった（§5.3）。

### 3.6 実装上の工夫：幅を 8 の倍数に揃える

fp16 の行列積は、幅が 8 の倍数でないと Tensor Core が効かずに遅くなる。残す幅を、ステップごと（q / v はヘッドごと）に 8 の倍数へ切り上げる。丸めなしでは FLOPs −50% でスループット 0.79 倍（未枝刈りより遅い）だったが、丸めると 1.22 倍になった。精度は下がらない（§5.8）。

### 3.7 手法名の対応

| 名前 | 内容 |
|---|---|
| `paper_step` | bViT 論文の重要度 \|E g\|、各ステップ・各層で同じ割合（論文方式を同じ単位に移植） |
| `paper_shared` | 同じ重要度をステップ方向に合計、全ステップ共通マスク |
| `fisher_step` | Fisher、各ステップ・各層で同じ割合 |
| `shared_joint` | 全ステップ共通マスクのうち最良の順位（交差項込み Fisher、FLOPs 当たり）＝ループ非対応の構造化 Pruning |
| `alloc` | Fisher ＋ ステップ × 層をまたぐ 1 本の順位 |
| `joint` | `alloc` ＋ ステップ間交差項 |
| `*_iter` | FLOPs 5% ごとに枝刈り後のモデルで重要度を測り直す |
| `*_floor` | 各ステップが各層の 10% を必ず残す |
| `*_mc` | 重要度を平均置換で測り、平均置換で除去 |
| `*+bc` | マスクは元の手法のまま、平均補正だけを後付け |
| `random_alloc` | 残す個数は提案と同じ、どれを残すかはランダム |
| **提案 = `rot` `joint_mc`** | 基底回転 ＋ 平均置換 ＋ Fisher ＋ 交差項 ＋ 1 本の順位 |

## 4. 実験設定

- モデル：
  - bViT-S / Tiny-ImageNet：64×64、top-1 55.71%、2.848 GFLOPs
  - bViT-S / CIFAR-100：top-1 68.83%、2.841 GFLOPs
  - bViT-B / CIFAR-100：top-1 69.90%、11.202 GFLOPs
- 較正：学習画像 10,240 枚（学習時と同じ拡張を除いた変換）で重要度と平均を測る。測り直し（`*_iter`）は 1 回 2,560 枚。
- 目標：FLOPs を未枝刈りの 0.9〜0.3 倍（削減 −10〜−70%）。
- 評価：検証セット全体の top-1。**特記しない限り再学習なし**。
- 計算量：FLOPs は `count_flops` で算出。スループットは RTX 2080Ti・fp16・バッチ 256 で、未枝刈りと交互に 5 回測った比の中央値。バッチ 1 遅延も同様に測定。
- ばらつき：bViT-S / Tiny-ImageNet は較正画像を変えて 3 回（seed 42/43/44）。表の ± は標準偏差。他の設定は 1 回。
- 微調整（§5.7）：マスクと平均を固定し、共有重みだけを AdamW（lr 1e-4、cosine、label smoothing、学習時の拡張、mixup / EMA なし）で 3 エポック学習。全手法同じレシピで、未枝刈りモデルにも同じ微調整をかけて対照とした。

### 5.2 各要素の効果（切り分け）

![](../figures/bvit_s_tiny_imagenet/ablation.png)

bViT-S / Tiny-ImageNet、FLOPs −50% の top-1：

| 段階 | raw | rot |
|---|---:|---:|
| bViT 論文の重要度、各ステップ同じ割合（`paper_step`） | 25.0 | 29.9 |
| Fisher、各ステップ同じ割合（`fisher_step`） | 25.0 | 30.3 |
| ＋ステップ × 層をまたぐ 1 本の順位（`alloc`） | 39.5 | 42.6 |
| ＋ステップ間交差項（`joint`） | 38.1 | 43.5 |
| ＋平均置換を基準にした重要度（`joint_mc`、**提案**） | 46.5 | **49.7 ± 0.1** |
| 参考：測り直しあり（`joint_iter_mc`） | 45.2 | 48.3 ± 0.4 |
| 参考：個数は提案と同じでランダム（`random_alloc`） | 28.5 ± 2.1 | 23.4 ± 1.7 |

- **配分（1 本の順位）の効果が最も大きい**（+13〜15pt）。重要度の式を Fisher に替えるだけでは変わらない（25.0 → 25.0）。
- raw ではランダム選択でも、提案の配分を使うだけで `paper_step` を上回る（28.5 対 25.0）。「各ステップからどれだけ削るか」が精度を大きく左右する。rot ではランダムは不利になる（23.4）。回転で重要度が少数チャネルに集中するため。
- **交差項**は、平均置換なしでは効果が混在する。小〜中削減では効き（rot −40%：47.7 → 49.3）、−70% ではやや悪化する（27.3 → 25.0）。平均置換と組み合わせると全域でプラスになる。平均置換ありの `alloc_iter_mc` は 47.7、`joint_mc` は 49.6。−70% ではそれぞれ 33.1 と 37.7。
- **回転**は、どの手法でも +3〜6pt。
- **測り直し**は平均置換なしでは高削減域の悪化を防ぐが、平均置換と組み合わせると逆にわずかに悪化するため、最終形から外した。
- **下限（各ステップ 10% を保持）**は効果なし（`joint_iter_floor` ≈ `joint_iter`）。

![](../figures/bvit_s_tiny_imagenet/compensation.png)

### 5.5 同じ精度での実測速度（GPU と CPU）

![](../figures/bvit_s_tiny_imagenet/speed_vs_accuracy.png)
![](../figures/bvit_s_cifar100/speed_vs_accuracy.png)
![](../figures/bvit_b_cifar100/speed_vs_accuracy.png)

FLOPs が同じなら、幅を削る方式は、ブロック丸ごと（LayerNorm・softmax・カーネル起動も含む）を消すステップ削減より速くはなれない。比較すべきは**同じ精度での速度**である。下表は、提案の各点と同じ精度になるステップ数を線形補間で求め、その速度と比べたもの（数値は未枝刈りに対する倍率）。CPU は fp32・4 スレッド・バッチ 32 で、他のジョブと並行した測定のため ±5% 程度の誤差がある。

| 設定（提案の FLOPs 削減） | top-1 | 同精度のステップ数 | GPU 提案 / ステップ | CPU 提案 / ステップ |
|---|---:|---:|---:|---:|
| S / Tiny −30% | 54.0 | 8.9 | 1.07 / 1.34 | 1.19 / 1.30 |
| S / Tiny −50% | 49.6 | 7.4 | 1.22 / 1.60 | **1.61** / 1.58 |
| S / Tiny −70% | 37.7 | 5.7 | 1.51 / 2.07 | **2.37** / 2.03 |
| S / CIFAR −30% | 67.8 | 9.2 | 1.09 / 1.29 | 1.21 / 1.35 |
| S / CIFAR −50% | 64.3 | 7.6 | 1.29 / 1.57 | **1.68** / 1.55 |
| S / CIFAR −70% | 51.2 | 5.7 | 1.55 / 2.09 | **2.33** / 2.08 |
| B / CIFAR −30% | 69.7 | 8.9 | 1.14 / 1.34 | 1.21 / 1.33 |
| B / CIFAR −50% | 68.0 | 7.4 | 1.42 / 1.63 | 1.63 / 1.63 |
| B / CIFAR −70% | 60.5 | 5.3 | 1.86 / 2.26 | **2.54** / 2.24 |

- **GPU（2080Ti）**：全域で、同精度のステップ削減より 15〜30% 遅い。細い行列積では GPU の演算器を使い切れないため。
- **CPU**：低削減域では負けるが、−50% で互角、**−70% では提案が 13〜17% 速い**。演算性能が律速になるデバイスでは、FLOPs 削減がそのまま速度になりやすく、同じ精度で FLOPs を多く削れる提案が有利になる。
- **バッチ 1 遅延（2080Ti）**：提案は未枝刈りの 0.94〜1.46 倍と、**かえって遅くなる**。ステップ削減は 0.3〜0.7 倍に縮む。ステップごとの重み切り替えと並べ替え（index 操作）がカーネル起動を増やすため。組み込み用途でバッチ 1 推論に使うには、この実装のままでは不向き。

### 5.6 どこが削られるか（配分とユニットの再利用）

![](../figures/bvit_s_tiny_imagenet/allocation.png)
![](../figures/bvit_s_tiny_imagenet/unit_reuse.png)

bViT-S / Tiny-ImageNet、提案。

- **FFN**：ステップ 2 と 7〜9 で多く残し、3〜5 と最終の 11〜12 で大きく削る。
- **QK**：ステップ 1 と最終ステップを大きく削る。最終ステップは −70% で 0%、つまり注意機構が恒等的な平均になる。
- **V**：中盤（2〜9）はほぼ残し、終盤（10〜12）で急に削る。
- ユニットの再利用（−50%）：
  - QK チャネルの約 40% は、どのステップでも使われない（共有重みから実質的に消せる）。
  - FFN ニューロンは平均 6 ステップ程度で使われる。
  - V チャネルは 9〜11 ステップで使われる。

各ステップから同じ割合を削る方式では、こうした偏りを使えない。これが §5.2 で配分の効果が大きかった理由と考えられる。bViT 論文の「ヘッド・ニューロンがステップごとに異なる役割を持つ」という観察とも整合する。

- 微調整すると差は縮む。**FLOPs −50% では、ステップ削減が提案に追いつく（S）か上回る（B）**。

- 提案は微調整なしで高精度なので、「再学習できない、または再学習のコストを払いたくない」場面で最も価値がある。

### 5.8 ばらつきと幅の丸め

- 較正画像を変えた 3 回の標準偏差は、提案（`joint_mc`）で 0.0〜0.3pt、`joint_iter_mc` で 0.1〜0.4pt。手法間の差（数 pt〜十数 pt）に比べて十分小さい。単発の値（§5.3・§5.5・§5.7 の 49.6 など）は seed 42 の結果。
- 幅を 8 の倍数に丸めない場合（rot、`joint_iter`、S / Tiny）の精度とスループットは次のとおり。丸めると精度は同じかやや良く（−50% で 43.5）、速度は大きく改善する。

  | | −10% | −30% | −50% | −70% |
  |---|---:|---:|---:|---:|
  | 精度 | 55.2 | 51.9 | 43.3 | 27.7 |
  | スループット | 0.57 | 0.66 | 0.79 | 0.91 |

## 6. 考察と限界

- **ループ構造を考慮すると効く点**：
  - ステップごとに別の配分を許すこと（最大の効果）。
  - 共有重みに由来するステップ間の交差項。
  - ステップごとの平均で置き換えること。
  
  ループ非対応の共通マスク（`shared_joint`）は、どの設定でも提案より大幅に悪い（S / Tiny −50%：25.9 対 49.6）。
- **速度**：FLOPs の削減ほどにはスループットが伸びず、特に GPU とバッチ 1 で弱い。現状の実装には次の無駄がある。
  - ヘッドごとに幅が異なると、最大幅までゼロ埋めして計算している。
  - ステップごとの重み選択と index 操作がある。
- **微調整後**：FLOPs −50% 程度ならステップ削減で足りる。提案の強みは「再学習なし」と「高削減域」に限られる。
- **評価の範囲**：
  - データセットは小規模（64×64 / 32×32）。
  - 較正画像を変えた反復は S / Tiny のみ。
  - CPU の測定は他ジョブと並行だった。
  - 小型 GPU や組み込み機器での実測はしていない。

## 7. 次の一手（提案）

1. **配分を実測遅延で行う**：§3.4 の FLOPs を、層・幅ごとの実測遅延テーブルに置き換える（HALP [16] 方式）。GPU で同精度のステップ削減に追いつけるかを見る。
2. **ヘッド幅を揃える制約**を入れて、ゼロ埋めをなくす。ステップごとの重みを事前に連結し、index 操作をなくす。バッチ 1 遅延の改善が狙い。
3. **微調整レシピの見直し**：未枝刈りも下がらないレシピにする（蒸留、低 lr、エポック増）。そのうえで −50% と −70% で再比較する。
4. ImageNet 規模（bViT-B、224×224）での検証。演算律速の度合いが変わり、GPU での速度比も変わるはず。
